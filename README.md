## 0.4.5 本页兑换结果与仓库更新

- “去兑换”不再跳到商品页面。先读取最新商品、资格及积分价，用户确认商品和实际积分后，只发送一次创建订单请求；本页显示真实兑换结果、官方拒绝原因及订单号。
- 依据官方前端的 `sku/info`、`trade/order/verify`、`trade/order/create` 和 `trade/order/detail` 流程实现；只支持虚拟大会员权益，不自动处理收货地址、绑定手机、验证码或跳转支付。
- 只有官方订单明确成功才显示成功。虚拟商品状态3仍为处理中，状态4为成功，状态5为失败并显示fail_reason；HTTP成功/请求code=0/余额变化不作为兑换成功证据。权益到账可能晚于订单成功，不宣称已延长会员。
- 兑换订单按账号和商品保存待核验记录。创建请求超时、HTTP异常或响应格式变化时不重发；再次点击只核验已有订单。若没有取得订单号则提示先在官方已兑换商品核对，避免重复扣分。
- 账号菜单内的版本中心接入本仓库latest.json，按version_code比较新旧，并提供仓库最新版下载入口；更新请求不携带B站Cookie。不恢复底部版本更新按钮，五连击彩蛋保留。
- 发布0.4.5 beta（versionCode 16），沿用既有本地测试签名。新增兑换流程与更新地址测试，通过10组Java测试和1组JavaScript探针测试，完成编译/签名/对齐检查；没有使用真实账号扣积分做交易测试。

- 已确认并修复上述代码缺陷，但没有真实账号设备的现场错误日志，不能断言这是手机上所有失败的唯一原因。未进行真机播放、后台持续播放及实际积分到账验收；网页权限、WebView和系统后台策略仍可能限制播放。

## 安装与使用

安装 `BiliPoints-0.4.5-beta.apk`，保留前版测试签名，可覆盖安装。右上角「账号」进入B站官方登录页面，输入凭据或完成验证，返回助手后同步。密码不保存为本应用的明文字段，WebView会话存于本机应用数据区。

- 「更新积分」：后台同步积分、会员状态和任务，并复核当前会话中已有的积分核验记录，不跳页。
- 「一键执行并核验」：检查签到、接取适用的任务、在主页后方加载官方浏览页面、提交对应任务完成请求、查询任务状态与新增积分流水。
- 「领取待领积分」：仅处理服务端明确标记的待领奖励，不将未知任务状态解释为可领取。
- 单项浏览任务：「执行并核验」，执行过程留在主页，显示结果与进度。
- 「停止执行」：取消后续步骤，当前已经发送的网络请求可能仍由服务端完成，之后可「更新积分」核验。

浏览页面由应用内WebView加载在主页后方，前端只显示执行状态，不跳转到可见浏览页。这里的“后台”指主页内处理，必须保持App在前台；切到系统后台会暂停浏览，长时间离开会超时。本版不是锁屏常驻服务。头像和会员徽标在账号资料同步后独立加载，加载失败保留占位或文本。

## 0.2.0 主要修复

此前会员购与装扮任务结束计时后，只做了数据刷新，未调用对应完成接口。当前版本增加：

- 追番、影视：现有浏览完成上报。
- 会员购：专用活动事件提交 `show.bilibili.com/api/activity/fire/common/event/dispatch`。
- 装扮：根据服务端实际任务编号提交完成请求。
- 查询大积分流水，通过新记录编号和任务说明匹配到账证据。
- 提交成功只表示请求被接受；必须同时看到服务端任务完成和本次新增的对应积分记录，才显示「已到账 +N」。
- 已完成但查不到新积分流水、流水接口不可用或格式变化、状态尚未更新时，显示「待确认」。不会用本地计时结束、接口code=0或总余额上涨直接声称某项已到账。
- 延迟到账可通过「更新积分」重新核验，无需自动重发完成请求。
- 页面重排为「积分与会员」「今日执行与结果汇总」「日常任务」「可展开详情」。

所有接口仍由B站服务端控制，活动事件和资格条件可能变化。此版没有使用真实账号做到账联调，因此不能保证上述兼容接口在当前账号可成功计分。隐藏页面不代表平台必然认可其浏览行为；未获认可时如实显示未确认，不伪造完成状态。

## 请求与数据

- API请求仅允许 `api.bilibili.com` 和一个固定的会员购活动接口；不接受任意远程地址接收Cookie。
- 浏览顶层导航限B站HTTPS域名；任务执行中阻止外部App自动跳转。
- 禁用WebView文件访问、混合内容、自动媒体播放，不添加JavaScript原生桥；不自动滚动或伪造观看心跳。
- 无广告、遥测、第三方账号收集服务或凭据日志。权限包括联网、播放前台服务、通知和唤醒锁，不申请无障碍权限。
- 关闭应用备份，账号菜单可清除本机会话；Cookie由Android WebView管理，并未作为额外加密保险箱存储。
- 核验基线与执行结果仅保存在当前进程内存。App重启后可以重新查询真实状态，但不会用丢失的历史基线推断新增到账。
